## Prioritized follow-up

1. Extend UI/API integration tests for project creation, invalid payloads,
   package gating, and media-range access.
2. Validate real FFmpeg interruption and retry using a disposable project,
   preserving partial diagnostics and never overwriting outputs.
3. Complete a fresh real-media UI workflow through both previews. The creator
   must personally review them before finalization or real package creation.
4. Expose tested editing controls in the UI and validate each on reviewed media.
5. Consider optional AI/asset features only after the core workflow is accepted.
6. Replace the single large filtergraph with bounded intermediate segment-group
   rendering before claiming support for long recordings with hundreds of cuts.
7. Keep the silence threshold explicitly configurable and review its output
   against representative noisy recordings before adopting any automatic
   noise-floor adaptation; a simplistic adaptive threshold can discard quiet
   speech.

The current `test001.mp4` review exports contain no approved cuts, captions,
title, or music. They are technical review previews, not finalized publishing
deliverables.
